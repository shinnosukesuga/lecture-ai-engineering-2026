# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 【前提】同じ質問「AIE2026の講座の宿題にある『3レベル』とは何ですか?」で比較した
  - 素のLLM（app.ask）は講座の情報を持たないため、「一般的には初級・中級・上級」などと推測で答え、実際の構成とずれていた。前置きや「講師に確認を」といった案内も多く、出力が長かった（695トークン）
  - エージェント（app.agent）は用語集をもとに「基礎・実装・発展の3段階で、いずれか1つに取り組めば完了」と講座の実際の内容どおりに答え、最後に「関連する回：第1回」を示した。回答も簡潔だった

- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「LoRA とQLoRAの違いは?」：search_glossary({'query': 'LoRA'})、search_glossary({'query': 'QLoRA'}) の2回
  - 「第2回の内容から確認問題を1問出して」：make_quiz({'lecture': 2}) の1回

- 1つの質問での LLM 呼び出し回数（`requests`）：
  - どちらの質問も2回（1回目：ツールを呼ぶかの判断、2回目：ツールの結果を受けて最終回答を生成）
  - search_glossary を2回呼んだ場合も requests は2回（tool_calls=2）で、1回目のリクエストで2つのツール呼び出しをまとめて出していた

- 追加したツールと、docstring に書いた説明：
  - ツール：make_quiz(lecture: int) -> str。用語集から指定した回の用語を集めて1つをランダムに選び、「○○の意味は？」という問題と、その用語の定義を答えとしてJSONで返す。該当する用語がない回はエラーメッセージを返す
  - docstring：「指定した回の用語から1つを選び、確認問題と答えを返す。『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う。」

## 宿題
- 取り組んだレベル：基礎
- やったこと：
  - 【前提】質問は「LoRA とQLoRAの違いは?」に固定し、--trace 付きで実行して比較した
  - 実験1：app/agent.py の INSTRUCTIONS から「必ず search_glossary で用語集を確認する」「用語集に見つからないことは『用語集にはない』と伝える」の2行を削除
  - 実験2：app/tools.py の search_glossary の docstring を「query には調べたい用語を1つだけ入れる（例: "LoRA"）」から「query に複数の用語を入れる場合は、スペース区切りでまとめて1回で渡す（例: "LoRA QLoRA"）」に変更（INSTRUCTIONS は元に戻した状態）

- 結果：
  - 実験1：変化なし。ツールは2回呼ばれ（引数 'LoRA'、'QLoRA'）、回答内容・関係する回（第2回）もほぼ同じ
  - 実験2：ツールの呼び出しが2回→1回になり、引数が 'LoRA QLoRA' にまとまった。input_tokens は 1196→909 に減少、output_tokens は 221→283 に増加（回答末尾にまとめ文が追加）。関係する回は第2回のまま

- 気づき・疑問：
  - INSTRUCTIONS から指示を消しても、docstring に「答える前に使うこと」が残っていたため、検索する挙動は変わらなかった。INSTRUCTIONS も docstring も、どちらもモデルが読むプロンプトとして効いている
  - 削除した2行目（用語集にない場合の指示）は、用語集にある語を聞いた今回の質問では発動しないため、効果を確認できなかった。指示の効果は、その指示が必要になる質問でしか測れない
  - docstring の例の書き方に、モデルは強く従う。説明文の書き方でツールの使われ方が変わる
  - 呼び出し回数が減ると入力トークンは減るが、回答の長さは揺れるため、コストは必ずしも下がらない（今回はわずかに増加）
